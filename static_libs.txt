❯ another question...its trivial to add to static libs (archives), correct? 

Yes, absolutely trivial! Static libraries (.a files) are just archives man-
  aged by the ar tool.

  Adding to an Existing Static Library

  # Add a new object file
  ar r libstrarith.a new_function.o

  # Add multiple files at once
  ar r libstrarith.a func1.o func2.o func3.o

  # The 'r' flag means "replace/insert" - adds if new, replaces if exists

  Common Operations

  # Create initial library
  ar rcs libstrarith.a str_reverse.o str_validate.o
  #  r = insert/replace
  #  c = create (suppress warning if new)
  #  s = create index (like ranlib)

  # Add more later
  ar r libstrarith.a str_palindrome.o

  # List contents
  ar t libstrarith.a

  # Remove a file
  ar d libstrarith.a old_function.o

  # Extract a file
  ar x libstrarith.a str_reverse.o

  Makefile Pattern

  OBJS = str_reverse.o str_validate.o str_palindrome.o

  libstrarith.a: $(OBJS)
        ar rcs $@ $^

  # Add new function - just add to OBJS and rebuild
  # The .a will be updated automatically

  Key advantages:
  -  Incremental updates - just compile new .o and ar r it in
  -  No need to recompile everything
  -  Can version control the .a or just the source
  -  Easy to inspect with ar t or nm

  So yes - you can grow your libraries organically as you write more utility 
  functions!
