Here's a summary of the optimization:

**What changed:** Before running 25-round Miller-Rabin on the reversed number,
`is_consec_sq_sum()` checks if it could even be of the form n² + (n+1)². This 
is a two-step filter:

1. **mod 4 check** (`mpz_fdiv_ui(p, 4) != 1`) — eliminates ~75% instantly
2. **perfect square check** (`mpz_perfect_square_p(2p - 1)`) — eliminates 
   nearly all the rest

**Why it's cheap:** `mpz_perfect_square_p` is O(M(n)) vs Miller-Rabin at 
O(25 × n × M(n)). The mod 4 check is essentially free.

**Result on the test run:** 126 out of 131 non-palindromic primes were filter-
ed before Miller-Rabin — only 5 needed the expensive test. That's a **96% re-
duction** in Miller-Rabin calls. The ratio will be even dramatic at larger 
search ranges because consecutive square sums get sparser (density ~1/sqrt(N)).

**Note on `emirps.dat`:** The output now only contains emirps whose reverse is 
also a consecutive square sum. This is a subset of the original, but Stage 4 
is the only consumer and it filters for the same property anyway, so the end 
result is identical.

## New CVPipe Pipeline

### Stage 1: Candidate Generation (unchanged)
- **Input:** `<max_prime>` from command line
- **Output:** `p01.dat` – `p16.dat`
- Generates all values of 2n² + 2n + 1 up to max_prime
- 16 threads, gatekeeper digit filters
- **~4,859s at 10^23**

### Stage 2: Unified Filter + Converse Hunt (merged Stages 2–4)
- **Input:** `p01.dat` – `p16.dat`
- **Output:** `converse.dat`, `otto_primes.dat`

For each candidate p:
1. Reverse digits → r
2. Is r ≡ 1 (mod 4)? — **~75% eliminated, essentially free**
3. Is 2r − 1 a perfect square? — **nearly all remaining eliminated**
4. Is p a palindrome? → flag for otto output
5. Miller-Rabin on p (25 rounds) — **only ~0-1 candidates reach this**
6. Miller-Rabin on r (25 rounds)
7. Both prime → **converse pair found**, write to `converse.dat`
8. Palindromic primes → write to `otto_primes.dat`

- **~100-150s at 10^23** (dominated by I/O read of pXX.dat)

### What's Gone

| Removed | Why |
|---------|-----|
| `primes01–16.dat` | Never created (~34 GB saved at 10^23) |
| `emirps.dat` | Never created |
| Stage 3 (`check_emirp_gmp`) | Folded into Stage 2 |
| Stage 3.5 (`check_palindrome_gmp`) | Folded into Stage 2 |
| Stage 4 (`check_converse_gmp`) | Folded into Stage 2 |

### Summary

```
OLD:  Stage 1 → p.dat → Stage 2 → primes.dat → Stage 3  → emirps.dat → 
      Stage 4 → converse.dat
      Stage 3.5 → otto_primes.dat

NEW:  Stage 1 → p.dat → Stage 2 → converse.dat → otto_primes.dat
```

- **5 stages → 2 stages**
- **4 intermediate file sets → 0**
- **~11,131s → ~5,000s at 10^23**
- **~102 GB intermediate I/O eliminated**
- **Billions of Miller-Rabin tests eliminated**

The 3 existing source files (`check_emirp_gmp.c`, `check_palindrome_gmp.c`, 
`check_converse_gmp.c`) stay in the repo but aren't part of the production 
pipeline anymore. The `Makefile` targets and `run` recipes would simplify too.
